# Detailed Task Breakdown: Node.js to Spring Boot Migration

This document provides a comprehensive, module-by-module checklist for migrating the Node.js/Express backend to Java Spring Boot. 

---

## Phase 0: Project Setup & Scaffolding

### 0.1 Spring Boot Initialization

- [x] **Generate project via Spring Initializr**
  - **Description**: Bootstrap the project using Java 17/21, Maven, and Spring Boot 3.3.x.
  - **Dependencies**: None
  - **Acceptance Criteria**: Base project compiles successfully using `mvn clean install` / `./mvnw compile`.
  - **Estimated Effort**: S

- [x] **Add required dependencies**
  - **Description**: Include dependencies in `pom.xml`: `spring-boot-starter-web`, `spring-boot-starter-data-jpa`, `spring-boot-starter-security`, `spring-boot-starter-validation`, `spring-boot-starter-actuator`, `flyway-core`, `h2`, `postgresql`, `ojdbc11`, `jjwt`, `bcrypt`, `mapstruct`, `apache-poi`, `thymeleaf`, `bucket4j`, `springdoc-openapi`.
  - **Dependencies**: Generate project via Spring Initializr
  - **Acceptance Criteria**: All dependencies are downloaded and project compiles without errors.
  - **Estimated Effort**: S

- [x] **Configure multi-profile application.yml**
  - **Description**: Setup configuration files for `dev` (H2), `staging` (PostgreSQL), and `prod` (Oracle) environments.
  - **Dependencies**: Add required dependencies
  - **Acceptance Criteria**: Application can start successfully using any of the three profiles.
  - **Estimated Effort**: M

- [x] **Setup project package structure**
  - **Description**: Create the base folder architecture (`com.murabha.cloud.*`): `config`, `controller`, `dto`, `entity`, `repository`, `service`, `security`, `middleware`, `exception`, `util`, `migration`.
  - **Dependencies**: Generate project via Spring Initializr
  - **Acceptance Criteria**: Directory structure exists and follows Spring Boot best practices.
  - **Estimated Effort**: S

### 0.2 Docker & CI

- [x] **Create backend-java/Dockerfile**
  - **Description**: Write a multi-stage Dockerfile (Maven build → JRE 17 runtime).
  - **Dependencies**: Spring Boot Initialization
  - **Acceptance Criteria**: `docker build` produces a working, optimized image.
  - **Estimated Effort**: S

- [x] **Update docker-compose.yml**
  - **Description**: Add the `backend-java` service alongside existing services.
  - **Dependencies**: Create backend-java/Dockerfile
  - **Acceptance Criteria**: `docker-compose up` successfully starts the Spring Boot application and database.
  - **Estimated Effort**: S

- [x] **Create GitHub Actions workflow**
  - **Description**: Setup CI pipeline for Java build, tests, and linting.
  - **Dependencies**: Spring Boot Initialization
  - **Acceptance Criteria**: PRs trigger the workflow, and it passes or fails correctly based on tests.
  - **Estimated Effort**: M

## Phase 1: Data Layer (Entities, Repos, Migrations)

### 1.1 JPA Entities

- [ ] **Create Branch entity**
  - **Description**: Map to `branches` table (id, code, name, address, phone, isActive, isOperational, createdAt, updatedAt).
  - **Dependencies**: Phase 0
  - **Acceptance Criteria**: Correct schema generated by Hibernate/Flyway matching Node Prisma schema.
  - **Estimated Effort**: S

- [ ] **Create User entity**
  - **Description**: Map to `users` table (id, username, name, email, password, role enum, branchId, isActive, lastLogin, createdAt, updatedAt).
  - **Dependencies**: Branch entity
  - **Acceptance Criteria**: Enum `UserRole` configured correctly, foreign key to Branch works.
  - **Estimated Effort**: S

- [ ] **Create Customer entity**
  - **Description**: Map to `Customer` table with unique constraint on `[bkCode, customerType]`.
  - **Dependencies**: Branch entity
  - **Acceptance Criteria**: Indexes and unique constraints correctly specified via JPA annotations.
  - **Estimated Effort**: S

- [ ] **Create MachineSale entity**
  - **Description**: Map to `MachineSale` table. Handle complex BigDecimal fields and relationships.
  - **Dependencies**: Customer entity, Branch entity
  - **Acceptance Criteria**: All fields, default values, and indexes mirror Prisma schema.
  - **Estimated Effort**: M

- [ ] **Create Installment entity**
  - **Description**: Map to `Installment` table with CASCADE on saleId and SET_NULL on paymentId.
  - **Dependencies**: MachineSale entity, Payment entity (stub)
  - **Acceptance Criteria**: Relations configured correctly to prevent orphan records.
  - **Estimated Effort**: M

- [ ] **Create Payment entity**
  - **Description**: Map to `Payment` table with default `paidAt` timestamp.
  - **Dependencies**: MachineSale entity
  - **Acceptance Criteria**: Entity correctly persists and links to MachineSale.
  - **Estimated Effort**: S

- [ ] **Create FollowUp entity**
  - **Description**: Map to `FollowUp` table with JSON column support for `logs`.
  - **Dependencies**: Customer entity
  - **Acceptance Criteria**: Hibernate handles the JSON column correctly (e.g., using Hypersistence Utils or standard mapping).
  - **Estimated Effort**: M

- [ ] **Create SystemSetting & AuditLog entities**
  - **Description**: Map configurations and audit trails. AuditLog needs JSON details support.
  - **Dependencies**: Phase 0
  - **Acceptance Criteria**: Entities map perfectly to existing database tables.
  - **Estimated Effort**: S

### 1.2 Repositories

- [ ] **Create Spring Data JPA Repositories**
  - **Description**: Create interfaces extending `JpaRepository` for all entities. Add custom query methods (e.g., `findByMachineSerialAndStatusNot`).
  - **Dependencies**: JPA Entities
  - **Acceptance Criteria**: All custom queries compile and pass basic integration tests.
  - **Estimated Effort**: M

### 1.3 Flyway Migrations

- [ ] **Create V1__initial_schema.sql**
  - **Description**: Export existing DB schema and configure as baseline Flyway migration.
  - **Dependencies**: None
  - **Acceptance Criteria**: Flyway successfully executes on an empty DB to create the exact Prisma schema.
  - **Estimated Effort**: M

- [ ] **Create Seed Migrations (V2, V3)**
  - **Description**: Create `V2__seed_settings.sql` and `V3__seed_admin.sql` (username: admin, bcrypt password).
  - **Dependencies**: V1 Migration
  - **Acceptance Criteria**: Default settings and admin user exist upon initial DB startup.
  - **Estimated Effort**: S

## Phase 2: Security & Auth

### 2.1 JWT Authentication

- [ ] **Implement JwtTokenProvider & Filters**
  - **Description**: Create utilities for generating access (15m) and refresh (7d) tokens, and `JwtAuthenticationFilter`.
  - **Dependencies**: Phase 1
  - **Acceptance Criteria**: Secure JWT parsing, correct SecurityContext population.
  - **Estimated Effort**: M

- [ ] **Implement AuthController**
  - **Description**: Create `/api/auth/login`, `refresh`, `logout`, `me` endpoints. Include bcrypt logic and Rate limiting (Bucket4j).
  - **Dependencies**: JwtTokenProvider
  - **Acceptance Criteria**: Users can login, receive HttpOnly cookies for refresh, and rate limits block brute force attempts.
  - **Estimated Effort**: L

### 2.2 RBAC & Branch Scope

- [ ] **Implement BranchScopeFilter & SecurityConfig**
  - **Description**: Servlet filter to enforce branch scoping based on UserRole. Create `@RequireRoles` annotation.
  - **Dependencies**: AuthController
  - **Acceptance Criteria**: HQ roles can read `x-branch-id`; Branch roles are restricted to their own `branchId` (prevents BOLA).
  - **Estimated Effort**: L

### 2.3 Audit Logging

- [ ] **Implement AuditService & Interceptor**
  - **Description**: Auto-capture user context, IP, and User-Agent for CRUD operations.
  - **Dependencies**: SecurityConfig
  - **Acceptance Criteria**: Sensitive operations write formatted JSON entries to `audit_logs` table.
  - **Estimated Effort**: M

## Phase 3: Core Business Services

### 3.1 CustomerService

- [ ] **Implement Customer CRUD & Logic**
  - **Description**: Implement `getAll`, `getById`, `create`, `update`, `delete`, `getCount`, `generateBKCode`.
  - **Dependencies**: Phase 1, Phase 2
  - **Acceptance Criteria**: BKCode uniqueness validated globally; delete blocked if active sales exist.
  - **Estimated Effort**: M

### 3.2 SaleService (MOST COMPLEX)

- [ ] **Implement Sale Creation Pipeline**
  - **Description**: Implement `create(dto, branchId)`. Handle serial uniqueness, installment scheduling, down payment recording.
  - **Dependencies**: MachineSale & Installment Repositories
  - **Acceptance Criteria**: Total installments + down payment perfectly equals `totalPrice`.
  - **Estimated Effort**: XL

- [ ] **Implement Payment Processing (pay)**
  - **Description**: Implement `pay(saleId, dto)`. Allocate payment via FIFO, update statuses.
  - **Dependencies**: Sale Creation
  - **Acceptance Criteria**: `sale.paidAmount` + `sale.remainingAmount` = `sale.totalPrice` ALWAYS.
  - **Estimated Effort**: XL

- [ ] **Implement Sale Modification Logic**
  - **Description**: Implement `previewPayment`, `void`, `voidPayment`, `recalculate`, `fullRecalculate`.
  - **Dependencies**: Payment Processing
  - **Acceptance Criteria**: Voiding resets states correctly; recalculation correctly redistributes remaining balance.
  - **Estimated Effort**: XL

### 3.3 InstallmentService & PaymentService

- [ ] **Implement Installment & Payment Management**
  - **Description**: Implement `getAll`, `getOverdue`, `pay`, `update`. Implement Excel export/import for updates.
  - **Dependencies**: SaleService
  - **Acceptance Criteria**: Batch imports parse correctly and update records transactionally.
  - **Estimated Effort**: L

### 3.4 FollowUpService

- [ ] **Implement FollowUp Operations**
  - **Description**: CRUD operations, `complete`, `getUpcoming` with branch scoping.
  - **Dependencies**: CustomerService
  - **Acceptance Criteria**: Follow ups accurately reflect customer interactions and deadlines.
  - **Estimated Effort**: M

  - **Dependencies**: Phase 3

- [ ] **Implement REST Controllers**

  - **Acceptance Criteria**: All endpoint paths and HTTP methods match the legacy API exactly.
  - **Estimated Effort**: XL

### 4.2 Global Error Handling

- [ ] **Implement @ControllerAdvice**

  - **Dependencies**: Controllers

  - **Estimated Effort**: S
